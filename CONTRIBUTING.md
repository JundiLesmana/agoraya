# Contributing to Agoraya.

1. Work from latest `origin/development` on one issue branch. Preserve uncommitted work.
2. Use Conventional Commits and open a PR to `development`.
3. Include acceptance criteria, exact test commands/results, security/data effects, and screenshots for UI changes.
4. Do not self-approve. Address review requests; rerun checks after revisions.
5. Release changes to protected `main` only through a reviewed release PR from `development`.

AI tools are contributors, not owners. Human reviewers are accountable for product, security, data, and deployment decisions.
